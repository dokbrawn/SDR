# Отчёты по занятиям

Здесь лежат отчёты: **одно занятие — один файл**. Никаких «1», «2», «3» и никаких
«неделя 4-5-6» одним куском: по названию файла должно быть понятно, о каком занятии речь
и когда оно было.

## Как устроено

```
reports/
├── README.md                              этот файл
├── TEMPLATE.md                            шаблон нового отчёта
├── assets/                                все картинки отчётов (скриншоты, графики)
├── lesson-01-02-fm-and-waterfall/         занятия 1–2, 08.09 и 15.09 (GNU Radio)
├── lesson-03-soapy-libiio/                занятие 3, 22.09 (SoapySDR, libiio)
├── lesson-04-06-iq-and-dual-pluto/        занятия 4–6, 29.09 / 06.10 / 13.10
└── lesson-07-08-tx-qpsk-shaping/          занятия 7–8, 20.10 / 27.10 (TX: QPSK, свёртка)
```

Именование каталога: `lesson-NN[-MM]-короткая-тема`. Внутри — `README.md`, чтобы GitHub
рендерил отчёт автоматически при открытии папки.

> Занятия 1–2 и 4–6 пока лежат в общих файлах (так сложилось исторически).
> Правильный вариант — разнести по одному файлу на занятие:
> `lesson-01-fm-receiver/README.md`, `lesson-02-waterfall-24ghz/README.md`,
> `lesson-04-iq-capture/README.md`, `lesson-05-dual-pluto-env/README.md`,
> `lesson-06-tx-rx-between-plutos/README.md`.

## Что обязательно должно быть в отчёте

Отчёт пишется **в первую очередь для себя** — это сырьё для собеседований и способ
увидеть собственный рост. Поэтому:

1. **Задача** — что просили сделать и что я сам для себя сформулировал.
2. **Ход работы своими словами** — не «собрана схема», а «сначала поставил X, потому что Y,
   не заработало, оказалось Z».
3. **Что не получилось** — обязательный раздел. Отчёт без неудач = отчёт, из которого
   ничего не видно. Тупики, неверные допущения, потраченное время, как вышел из ситуации.
4. **Результат** — число, график, лог. Не «работает», а «RMS 260 при gain 40 дБ».
5. **Вывод / что понял** — одна-три строки про суть явления, а не про то, что всё удалось.
6. **Артефакты** — ссылки на код (`src/`, `scripts/`) и картинки (`../assets/…`).
7. **Что дальше** — следующий шаг, который из этого следует.

## Чего в отчёте быть не должно

- Вылизанного текста «как из нейросети». Ровные абзацы без единой ошибки и без единого
  «не получилось» читаются как чужие.
- Пересказа документации вместо описания своей работы.
- Утверждений, которых нет в репозитории. Если в отчёте написано «проект на CMake с тремя
  целями» — этот CMake-проект должен лежать в git. Если написано «передаётся константа 8000» —
  в коде должна быть константа 8000, а не тон 10 кГц.
- Картнок без подписей и без ссылки на то, при каких параметрах они сняты.

## Скриншоты и графики

Все изображения — в `reports/assets/`, имена говорящие:
`rx_gain40.png`, `iq_zoom_between_bursts.png`, `waterfall_2437mhz.png`.
Вставка: `![подпись](../assets/имя.png)` + строка с параметрами съёмки под картинкой.
`.pcm`-записи (сотни МБ) в git не коммитим — они в `.gitignore`, в отчёт идёт только график.
